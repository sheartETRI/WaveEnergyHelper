# 운영 안내

## 설정의 실제 소비자

| 설정 | 위치 | 영향 |
|---|---|---|
| 심볼·시간봉·지표 파라미터 | `config/settings.py` | 앱·연구의 지표 정의, 고정 감사 대상 |
| 기본 푸시 대상 | `notify/settings.py`의 `PUSH_TARGETS` | BTCUSDT × 1h·2h·4h·6h·12h·1d·2d |
| 발송 제외 종류 | `notify/plan.py`의 `SEND_DISABLED_KINDS` | LL은 검출·기록하되 발송 제외 |
| 이전 알림 대상 | `config/settings.py`의 `PUSH_WATCHLIST` | `--legacy-signals` 경로만 사용 |
| 푸시 실행 간격 | CLI의 `--loop`, `--offset` | 기본 서비스는 300초 격자, 정각 대비 60초 뒤 |
| OHLCV 저장 위치 | `WEH_OHLCV_STORE_DIR` 또는 `OHLCV_STORE_PARAMS` | 앱·CLI·스캔의 공용 저장본 |
| 토큰·이력·로그 | CLI의 `--token`, `--state`, `--log` | 기본은 저장소 루트의 `token.txt`·`pushbullet_state.json`; 로그는 지정할 때만 생성 |

기본 설정의 값과 발송 종류를 유지했습니다. CLI `--symbols`·`--intervals`로 해당 실행의 대상을 바꿀 수 있습니다. 화면 신호 전체가 기본 푸시 대상인 것은 아닙니다.

`scripts/push_alarms.py`는 옵션·실행 주기를 조립하며 기본 순회는 `notify/poller.py`, 구형 경로는 `notify/legacy_signals.py`에 있습니다. 구형 경로도 `data/frames.py`의 공용 적재를 사용합니다. 이전에 스크립트 모듈에서 가져오던 `PushState`·`run_once` 등은 같은 이름으로 계속 사용할 수 있습니다.

## 실행과 중지

```powershell
# 인자와 기본 경로 확인 (전송 없음)
python scripts/push_alarms.py --help
# 수신·계산·보낼 내용 확인 (발송·이력 기록 없음)
python scripts/push_alarms.py --dry-run
# 실제 운영: 5분 격자, 정각보다 1분 뒤
python scripts/push_alarms.py --loop 300 --offset 60 --log logs/push_alarms.log
```

`--dry-run`도 Binance 수신과 OHLCV 캐시 쓰기는 할 수 있습니다. `--test`는 실제 외부 테스트 알림을 1건 보냅니다. 자동 테스트·정리 검증에는 사용하지 않습니다. 실행에는 저장소 루트 `token.txt` 또는 `--token` 경로에 Pushbullet 토큰 한 줄이 필요합니다. 토큰을 로그·문서·Git에 넣지 않습니다.

터미널 실행은 Ctrl+C로 중지합니다. 앱은 `python -m streamlit run main.py`로 실행하고 Ctrl+C로 중지합니다. Windows 재시작 도우미 `scripts/run_app.ps1`는 이 저장소의 Streamlit 프로세스를 종료한 뒤 다시 기동하므로 재시작할 때만 사용합니다.

Linux에서는 `deploy/push_alarms.service`의 사용자·작업 디렉터리·가상환경 경로를 실제 설치에 맞춰 적용합니다. `systemctl status weh-push`, `journalctl -u weh-push -f`로 상태와 로그를 확인하고 `systemctl stop/restart weh-push`로 관리합니다. 동일한 상태 파일을 쓰는 폴러를 여러 개 동시에 실행하지 않습니다.

## 발송·저장 규칙

- 마감 봉만 감시합니다. 수신 실패로 저장본을 사용한 셀은 발송 대상에서 제외합니다.
- 최초 스캔 종류는 과거 이벤트를 기록만 하고, 이후 새 이벤트부터 발송합니다. 중복 이벤트는 이력 키로 차단합니다.
- 전송 실패는 성공 이력에 남기지 않아 다음 순회에서 재시도할 수 있습니다.
- 일일 요약은 한국 시간 09:00 이후 그날 첫 순회에서 한 번입니다. UTC 날짜 키로 중복을 방지합니다.
- `pushbullet_state.json`에 전송 이력·종류별 초기화 상태·daily·ledger가 함께 있습니다. 초기화하면 최초 스캔 동작이 다시 적용됩니다.
- 이전 형식 이력은 `.legacy.json` 경로로 이관합니다. 기존 이력을 임의로 새 형식에 합치지 않습니다.

```powershell
# 후보 기록을 CSV로 추출 (Pushbullet 전송 없음)
python scripts/push_alarms.py --export-ledger artifacts/ledger.csv
```

내보낼 상위 폴더는 미리 만듭니다. `artifacts/`는 Git 제외 대상입니다.

## 장애 대응과 복원

| 현상 | 확인·대응 |
|---|---|
| 시세 수신 실패 | 로그의 HTTP 상태·주소 확인. 403/451은 대체 주소 경로 확인. 앱의 stale 안내와 마지막 수신 시각 확인 |
| 일부 시간봉 데이터 없음 | 원본 시간봉·리샘플 완성 여부·누락 봉 확인. stale 셀은 다음 정상 수신까지 발송 제외 |
| 알림 없음 | 토큰 유무, 최초 종류 스캔, 중복 이력, LL 발송 제외, 마감 봉 여부를 순서대로 확인 |
| 발송 실패 | 로그의 전송 실패·반환 상태 확인. 실패 이력을 성공으로 수동 기록하지 않음 |
| 오래된 앱 표시 | 사이드바 기동 코드·시각·경로 확인 후 해당 앱 재시작 |

상태 파일 백업·복원은 폴러를 중지한 상태에서 합니다. `pushbullet_state.json`과 필요한 legacy 이력·누적 ledger를 복사하고, 복원 후 경로·JSON 읽기와 `--dry-run`을 확인합니다. 토큰 백업은 별도로 접근을 제한합니다. OHLCV는 재수신 가능하지만 누적 관측·전송 이력은 재생성 캐시로 취급하지 않습니다.

종료 코드 1은 발송 실패 또는 셀 오류, 2는 토큰 등 실행 조건 오류일 수 있습니다. 구체 원인은 로그와 해당 명령의 도움말로 확인합니다. 서비스 재시작은 기존 상태 파일을 유지한 채 수행합니다.
