# Streamlit 화면 성능 개선

적용일: 2026-10-28. 기본 차트 첫 표시와 데이터가 같은 상태의 재실행 시간을 줄였습니다.

## 확인한 병목과 변경

기존 `st.tabs`는 기본 차트 탭을 볼 때도 숨겨진 알람 탭을 실행했습니다. 매번 8개 시간봉의 TF 레이더·기준 TF 레이더를 계산하고 현재 시간봉의 추적·기울기 표·복사 텍스트까지 만들었습니다.

설치된 Streamlit 1.58.0의 `on_change="rerun"`과 탭의 `.open` 상태를 사용해 선택한 탭만 실행하도록 바꿨습니다. 첫 차트는 현재 시간봉 추적·구조와 필요한 상위 게이트만 실행합니다. 알람 탭을 열면 기존 전체 레이더와 표·복사 텍스트가 표시됩니다. CLI는 알람 탭을 명시적으로 선택합니다.

`display/analysis_cache.py`는 기존 순수 추적·구조 계산의 결과를 재사용합니다. 키에는 전체 OHLC·이평·스토캐·시각 인덱스와 관찰 길이를 포함합니다. 과거 봉 수정도 반영하고, 결과를 돌려줄 때 사본을 사용합니다. MACD·RSI 선택은 추적 계산에 영향을 주지 않아 캐시를 공유합니다. 유효기간은 600초, 종류별 최대 64개입니다.

## 동일 조건 측정

Windows / Python 3.10 / Streamlit 1.58.0, BTCUSDT 1h, 합성 Binance 응답과 격리된 임시 저장소로 AppTest 실행을 측정했습니다. 최초 실행 1회와 같은 데이터의 반복 실행 2회이며 실제 외부 네트워크·브라우저 페인트·Python 프로세스 기동 시간은 포함하지 않습니다.

| 측정 | 변경 전 | 변경 후 |
|---|---:|---:|
| 차트 최초 실행 | 13.69초 | 4.34초 |
| 같은 데이터 반복 실행 평균 | 1.87초 | 0.30초 |
| 차트 최초 실행의 합성 HTTP 요청 수 | 8회 | 2회 |
| 조회 시간봉 | 1h·1w·3d·1d·12h·6h·4h·2h | 1h·4h |

이 조건에서 최초 실행은 약 68%, 반복 실행은 약 84% 단축됐습니다. 실제 환경의 시간은 통신 지연·저장본·종목·시간봉에 따라 달라집니다. 알람 탭의 최초 전체 시간봉 계산은 필요할 때 수행하므로 별도 대기 시간이 있을 수 있습니다.

측정 원본은 로컬 `artifacts/performance-before.json`, `artifacts/performance-after-chart.json`에 있습니다. 코드·데이터 변경 전후에 같은 합성 응답을 사용했습니다.

## 동작·검증 범위

- 차트 기본 실행에서는 TF 레이더를 호출하지 않고 알람 탭 선택 후 실행하는지 AppTest로 확인합니다.
- 캐시 결과가 원본 추적 결과와 같은지, 과거 봉·시각·관찰 길이 변경 시 다시 계산하는지 확인합니다.
- MACD·RSI 변경과 열 순서 변경은 결과를 재사용하며 반환값 수정이 캐시를 오염시키지 않는지 확인합니다.
- 기존 알람 표·전체 복사·CLI·stale 저장본 동작을 검사합니다.

운영 회귀 결과는 **387 passed, 12 skipped, 2 deselected**입니다. skip은 선택 의존성인 Plotly 비교 검사이며 실제 외부 수신·브라우저 검사는 별도 선택 범위입니다.

탭 전환은 재실행을 유발하므로 차트 확대 상태가 초기화될 수 있습니다. 기존 지표·신호·후보 창·상위 게이트 정의와 외부 푸시 발송 정책은 바꾸지 않았습니다.

실행 중인 Streamlit을 재시작하면 새 탭 실행 방식과 계산 캐시가 적용됩니다.
