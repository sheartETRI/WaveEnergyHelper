# 개발 환경과 검증

현재 기준 환경은 Windows, Python 3.10.9입니다. 기존 환경의 직접 의존성 버전은 [environment.json](environment.json)에 기록했습니다. 다른 Python 버전의 지원은 별도 검증 대상입니다.

## 설치 범위

| 파일 | 목적 |
|---|---|
| `requirements.txt` | 앱·알림 운영: requests, pandas, streamlit, NumPy, 표 스타일용 Jinja2 |
| `requirements-dev.txt` | 운영 패키지 + pytest |
| `requirements-research.txt` | 개발 패키지 + Plotly·Matplotlib·mplfinance |
| `requirements-browser.txt` | 개발 패키지 + Playwright |
| `requirements-legacy.txt` | 이전 명령 호환용 연구 설치 진입점 |

직접 의존성은 검증 기준 버전으로 고정하고 전이 의존성은 `constraints-py310.txt`로 고정합니다. 이 파일은 Windows의 Python 3.10 새 환경에서 설치한 결과입니다.

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest --suite runtime -q
```

## 테스트 범위

`pytest.ini`는 `tests/`만 수집하고 기본적으로 실제 네트워크·브라우저 검사를 제외합니다. `--suite runtime`은 연구 모듈을 import하기 전에 수집에서 제외하여 운영·개발 의존성만으로 실행할 수 있게 합니다. `tests/conftest.py`는 파일별 runtime/research와 개별 network/integrity 마커를 부여합니다. 외부 HTTP는 network 마커가 없는 테스트에서 차단하여 누락된 분류를 탐지합니다. Mock 응답을 사용하는 UI 검사는 오프라인 범위입니다. 이전 전이 레이더·GT 계측 검사는 연구 범위에 포함됩니다.

```powershell
# 운영 회귀
python -m pytest --suite runtime -q
# 연구 포함 오프라인 전체 (선택 의존성 설치 필요)
python -m pip install -r requirements-research.txt
python -m pytest -q
# 고정 코드와 이동 출처
python -m pytest --suite runtime -m integrity -q
# 실제 데이터 수신: 명시적으로 선택
python -m pytest -m network -q
# 브라우저 설치·차트 검사
python -m pip install -r requirements-browser.txt
python -m playwright install chromium
python -m pytest --suite runtime -m browser -q
```

`validation/*_ui_playwright.py`는 당시 UI에 대한 수동 검증 자료입니다. 기본 테스트 수집에 포함하지 않습니다. `git show` 기반 검사에는 원본 커밋이 필요하며 CI는 전체 Git 이력을 가져옵니다. 통과·실패·skip·선택 제외를 각각 보고합니다.

테스트의 OHLCV 저장소는 임시 디렉터리로 격리합니다. 실제 `data/cache`, 토큰, 푸시 이력에 테스트 값을 쓰지 않습니다. 실제 외부 알림은 테스트에서 전송하지 않습니다.
